# 构建与安装

## 一、环境准备

只有 **WSL2（Ubuntu 22.04）** 是必需的，Windows 原生不支持 Theos。

```bash
# 1) 装依赖
sudo apt update
sudo apt install -y git curl make clang perl dpkg fakeroot libssl-dev

# 2) 装 Theos
export THEOS=$HOME/theos
git clone --recursive https://github.com/theos/theos.git $THEOS
export PATH=$THEOS/bin:$PATH

# 3) 装 iOS SDK（编译头文件）
#    公开 SDK 一般到 iOS 16.x，本项目用 iPhoneOS16.5.sdk 即可
ls $THEOS/sdks
```

> 建议把 `export THEOS=...` / `export PATH=...` 两行写进 `~/.bashrc`，省得每次重敲。

---

## 二、编译

### 2.1 音量引擎

```bash
cd src/VolManAudioQueue
make package FINALPACKAGE=1
```

### 2.2 设置面板净化模块

```bash
cd src/VolManPrefsClean
make package FINALPACKAGE=1
```

产物在各自的 `packages/` 目录下。

### 2.3 关键编译选项

```make
ARCHS = arm64                     # 必须单切片！
TARGET = iphone:clang:16.5:15.0
THEOS_PACKAGE_SCHEME = rootless   # 根前缀 /var/jb
```

**为什么 `ARCHS` 必须只有 arm64？**

iOS 15 之后系统对 arm64e 切片的 ABI 版本有要求。用较旧工具链编出来的 arm64e 切片
带的是旧 ABI 标记（`cpusubtype = 0x00000002`），系统进程加载时会**直接进安全模式**；
而 arm64 单切片不受这条限制。

检查方式：

```bash
lipo -archs 你的.dylib        # 应只输出 arm64
```

### 2.4 注入过滤器

```text
VolManAudioQueue.plist   { Filter = { Bundles = ( "com.apple.UIKit" ); }; }
VolManPrefsClean.plist   { Filter = { Bundles = ( "com.apple.Preferences" ); }; }
```

`Bundles = ("com.apple.UIKit")` 是 CydiaSubstrate 官方推荐的「注入所有 UIKit App」写法。
**不要**用 `Classes = ("UIApplication")` —— 那个只匹配静态链接进主可执行文件的类，等于不生效。

## 三、打包

仓库提供两套打包配置，放在 `packaging/`：

| 配置 | 包名 | 用途 |
|---|---|---|
| `control.patch` + `Makefile.patch` | `com.local.volmanaudioqueue` | **补丁包**：只装重写的引擎和净化模块，装在已装原版插件之上 |
| `control.full` + `Makefile.full` | `com.local.volmanaudioqueue.full` | **全量包**：自带全套组件，适合全新安装 |

打包思路：

1. 把要打进包里的文件放到 `layout/` 下（Theos 在 rootless 模式下会自动给
   `layout/Library/...` 补上 `/var/jb` 前缀，`layout/DEBIAN/` 除外）；
2. `make package FINALPACKAGE=1` 生成 `.deb`。

补丁包的 `layout/` 只需要自己的两个模块；全量包还需要从原版 deb 里提取
设置面板、HUD、主模块（**排除有杂音的 `VolumeManagerAudioQueue`**）一起放进去。

安装脚本（`packaging/DEBIAN/`）负责：

- 安装时把原版有杂音的音量模块改名停用（后缀 `.vmaq-backup`）；
- 卸载时自动还原；
- 按 Rootless 规则创建真实数据目录 `/var/jb/var/mobile/Library/VolumeManager-sunshinesong/`。

---

## 四、安装

1. 把 `.deb` 传进 iPhone（AirDrop / Filza / scp 都行）；
2. 用 **Sileo** 或 Filza 安装；
3. 执行一次 **respring（注销）**；
4. 打开 **设置 → VolumeManager**，给需要的 App 设一个音量值。

调完音量后如果某个 App 没变化，先确认那个 App **正在播放音频**再调一次 ——
钩子是在音频流建立的时候挂上去的。

## 五、常见问题

### 装完直接进安全模式

99% 是 dylib 的架构问题。检查：

```bash
lipo -archs xxx.dylib
```

如果输出里有 `arm64e`，说明工具链产出的 arm64e 切片 ABI 版本太旧，请改成单 arm64 切片重编。

### 配置读不到（音量怎么调都没反应）

Rootless 越狱下真实目录是：

```
/var/jb/var/mobile/Library/VolumeManager-sunshinesong/
```

原版模块写的是**不带 `/var/jb` 前缀**的裸路径，靠越狱运行时的路径映射才碰巧能用。
自编译的模块不走那层映射，必须显式补前缀或做多路径探测。

另外注意一个坑：**libroot 的 `stat()` 钩子会就地改写调用方传入的 C 路径缓冲区**。
如果直接对同一个 `NSString` 反复取 `fileSystemRepresentation` 再传给 `stat()`，
字符串缓存缓冲区会被写脏，日志里打印出来的路径就变成容器路径了。正确做法是先造一份临时副本。

### Filza 里看不见 `/jb` 文件夹

Filza 有两个视角，「越狱根」视角下 `/var/jb/var/mobile/...` 显示为
`/var/mobile/...`。这两个是**两个不同的目录**，不是同一个东西的两种叫法 ——
路径改动前一定先确认自己在哪个视角里。

### 净化模块没生效

净化是按**文案匹配**做的（精确匹配 + 关键词兜底）。如果作者改了界面文案，
净化会失效但不影响使用。日志在：

```
/var/jb/var/mobile/Library/VolumeManager-sunshinesong/vm-prefsclean.log
```
