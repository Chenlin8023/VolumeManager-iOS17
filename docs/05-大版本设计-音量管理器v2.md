# 05 · 大版本设计稿 ——「音量管理器」v2.0（面板自写 / 白名单 / HUD 透明）

> 设计已定稿（2026-11-18），四个路线分歧点由用户拍板。实施按 §七 顺序分四步，每步单独实机验证。
> 基线 v1.3.4；本文承接 `04-大版本现状摘要-面板与白名单.md`，§五 七个待决问题在 §二 全部关闭。

## 一、产品目标（用户 2026-11-18 提出四项）

1. 插件改名 **「音量管理器」**（显示名；`Package:` 不变）。
2. 控制面板改造：原「已设置音量的应用列表」升级为**白名单模式**——扫描已装 App，音频播放类默认勾选；
   钥匙串/设置/家人共享等系统应用**不再无条件注入**（默认不勾、可手动勾选补充）。
3. 音量面板（HUD）背景**全透明**，取消磨砂玻璃遮挡。
4. （随 2 引出）白名单外的 App 引擎完全不注入（含混音层，见 §二 Q5）。

## 二、待决问题关闭（04 §五 → 定案）

| # | 问题 | 定案 |
|---|---|---|
| 1 | 白名单落在哪层 | **ctor 层裁决**。filter 保持 `com.apple.UIKit` 宽口径不变（新装 App 免重发 filter），引擎 ctor 读白名单决定装/不装。既有「不装」路径复用，改动最小 |
| 2 | 白名单存储 | **独立文件** `<配置目录>/appwhitelist.plist`。不进 volumeInfo.plist——闭源面板会整写该文件，加 key 会被覆盖丢失；自写面板接手后同样保持分离 |
| 3 | 名单来源 | **面板内扫描 LSApplicationWorkspace**（Settings 进程运行时可用，NotifierIcons 等有先例）。默认勾选 = `UIBackgroundModes` 含 `audio` 的 App + volumeInfo 已配置 App；`applicationType == System` 默认不勾（钥匙串/设置/家人共享都在此组）但照常列出可勾 |
| 4 | 面板改造路线 | **自写面板整体替换**（用户拍板）。Swift+Orion，走 GitHub Actions CI（Apple 工具链；VolMan 仓库现无 workflow，需新配，参照 Jikan 仓库 CI）。闭源 `VolumeManagerPrefs.bundle` 与净化模块 `VolManPrefsClean` 退役 |
| 5 | 混音层是否收窄 | **随白名单收窄**（用户拍板）。名单外 App 全不装（含混音 hook）。代价（已接受）：名单外 App 激活音频可能打断白名单 App 同播 = iOS 原生行为；音频类默认已勾，主流场景覆盖 |
| 6 | 兼容迁移 | **volumeInfo 已配置项 = 白名单种子**（首次扫描时并成默认勾选）。**白名单文件缺失 = v1.3.4 行为**（配置存在就装）——升级后未首次扫描前绝不回退 |
| 7 | JailFools 副本 | 无新耦合。副本里就是引擎本体，白名单在 ctor 读文件裁决，副本刷新逻辑照旧 |

**升级清理（关键）**：postinst 必须删除旧组件残留文件——`VolumeManager.dylib(.plist)`、`VolumeManagerPrefs.bundle/`、`VolManPrefsClean.dylib(.plist)`、旧 entry `VolumeManagerPrefs.plist`。否则残留的 `VolumeManager.dylib` 仍会被 AVAudioSession filter 继续注入，白名单语义失效且双 hook 复活。

## 四、引擎改动（`src/VolManAudioQueue/Tweak.xm`，本地管线）

### 1. 白名单裁决（ctor）—— **已实施（步骤①）**

- 新增 `VMWhitelistDecide()`：读 `appwhitelist.plist`，格式 `{ version:1, mode:"whitelist", enabled:[bid…] }`，引擎只认 `enabled` 数组。
  查找顺序（沿用旁路文件的目录候选惯例，非 8 路径全探测）：
  三个数据目录（`VM_DIR_JB` / `VM_DIR_PLAIN` / `VM_DIR_JBROOT`）→ Preferences 同步副本
  `/var/mobile/Library/Preferences/com.local.volmanaudioqueue.appwhitelist.plist`（沙箱 App 兜底，postinst 安装时同步，面板落定后由面板双向同步）。
- 三态语义：
  1. **文件不存在**（所有候选均无）→ `Legacy`：v1.3.4 行为（配置存在就装），日志注明「白名单未初始化→兼容模式」——升级后未首次扫描前绝不回退；
  2. **文件存在但不可解析 / 无 enabled 数组** → 按空名单（`Out`，fail-closed）：宁可暂不注入，也不悄悄变回「全进程注入」；文件存在性用 `fileExistsAtPath` 单独判定，防止「存在但损坏」被误判成「不存在」滑进兼容模式；
  3. **enabled 含 bid** → 装（音量+混音）；不含 → **全不装**（含混音），日志一行原因。
- 裁决顺序（ctor 内，`skip`/`forced` 语义不动）：skip（SpringBoard/PluginKitPlugin/无 bid）→ **调试旁路 `vmaq-force` 优先于白名单**（排障通道不受名单约束）→ 白名单 → 配置存在性。
  白名单是**进程启动时的一次性裁决**，改名单重启 App 生效；音量值仍走 0.5s 轮询热刷新（两种语义不同，日志与面板提示写明）。
- 日志版本行升 `v2.0.0 注入`，日志头带 `白名单=<verdict>` + 独立一行「白名单：文件路径 | 原因」。

### 2. HUD 透明补丁 —— 载体已变更：独立 FAT 模块 `VolManHUDPatch`（CI 构建）

- **关键定案（2026-11-18 实测）**：引擎（arm64 单切片）从未进入任何系统进程——SpringBoard/设置等
  arm64e 进程静默拒载 arm64 dylib（硬规则 3 的一般化）。证据：中央日志从未生成过（三个数据目录
  均无 vmaq.log）、PrefsClean 的运行时状态 key 与日志（含 /tmp 镜像）在设置里从未出现，
  唯一一条净化日志来自 QQReaderUI（App 进程）。**由此修正两个历史认知**：
  ① 历年面板净化的实际效果全部来自打包期静态层（等长清空），运行时层从未生效；
  ② 中央日志概念作废——**容器日志是唯一真实日志通道**（对 rootless 线的系统进程而言）。
  「系统应用不再无条件注入」的真正全进程注入者是原版 `VolumeManager.dylib`（FAT 双切片，
  它确实在系统进程里跑）——步骤④移除它即精确命中目标。
- **载体**：独立模块 `src/VolManHUDPatch/`，filter 只指 SpringBoard，**FAT 双切片（arm64+arm64e）**，
  **必须 CI（Apple 工具链）构建**——本地 clang19 的 arm64e 切片过不了 PAC 关（硬规则 8）。
  本地 WSL 禁止构建本模块；产物人工下载到 `tools/hudpatch-prebuilt/`，`build-rootless.sh` 打入 full 包
  （缺席不阻塞构建）。CI = `.github/workflows/hudpatch.yml`（参照 Jikan build.yml），
  内置 lipo 硬断言（arm64+arm64e 双切片必须齐全）。
- **职责**：①探针（`vmaq-hud-debug` 开关，dump 闭源 HUD 视图树到 `vmaq-hudpatch.log`，一次性）
  ②透明化（默认生效；`vmaq-hud-opaque` = 恢复原样）：所有 `UIVisualEffectView` effect 置 nil、
  HUD 自有类（类名含 VolumeManagerSBHUD）与窗口背景清透明、音量条/文字等 Apple 类不动。幂等，每次呼出执行。
- **挂点**：`VMViewController viewDidAppear:`/`viewDidLoad`、`VMHUDView didMoveToWindow`，
  dyld add_image 回调等 HUD 镜像加载；`method_setImplementation` 手动 swizzle，
  带「方法须由类自身实现」防误伤守卫（防误挂父类 → SpringBoard 全部视图一锅端）。
- **日志**：NSLog + 中央数据目录 `vmaq-hudpatch.log` + `/tmp` 镜像双写（SpringBoard 为 root，中央可写——
  这是全 rootless 线唯一真正能落中央的组件）。

## 五、自写面板（`VolManPrefsPanel.bundle`，CI 构建）

### 与引擎的契约（解耦面，与 04 §三一致）

写 `volumeInfo.plist`（原格式 `<bid>:{volume, appName}`）、写 prefs 域 `com.sunshinesong.volume-manager-prefs.plist`、写 `appwhitelist.plist`、发 Darwin 通知 `settingOnChanged`（引擎另有 0.5s 轮询兜底）。

### 页面结构（全中文，导航标题「音量管理器」）

- **根页**：总开关（key `isEnabledManagementAppVolume`）、启用混音（引擎 vmMix 配置）、HUD 显示条件。
  ⚠️ HUD 是闭源，显示条件读哪个 key **TBD**——实施第一步先导出现有 prefs 域拿全量 key 清单，自写面板必须写同名 key 否则 HUD 条件失联。
- **应用白名单页**（原应用列表升级）：
  - 进入异步扫描（LSApplicationWorkspace，不做缓存文件；卡顿若明显再上「上次结果缓存」）；
  - 每行 = 图标 + 名称 + 注入开关（PSSwitchCell）；默认勾选规则见 §二 Q3；
  - 已勾选行点入 → 音量滑杆子页（写 volumeInfo，原格式，兼容旧数据）；
  - 页脚提示语义：「未勾选的应用不会被注入，音量调整与混音对它们完全不生效」。
- 空白名单 = 全不装（用户自己勾的结果），面板给出显眼提示。

### CI 与打包集成

- 新增 `.github/workflows/panel.yml`（参照 Jikan 仓库 CI）：编译 `VolManPrefsPanel.bundle` → 上传 artifact/release。
- `build-rootless.sh`：优先用本地 `tools/panel-prebuilt/` 里的预编译 bundle；无则从 CI artifact 拉取。打进 full 包 layout `Library/PreferenceBundles/`。
- 面板 bundle 本身是独立 Mach-O：**不需要 PAC 数据补丁**（CI 产物自带认证）；但打包期 `ldid -S` 仍按 AGENTS.md 规则执行。

## 八、风险清单

- **同播回归**：移除原版 `VolumeManager.dylib` 后多 App 同播需 A/B 实测（步骤 4 前单独验证）。
- **HUD 条件 key 失联**：闭源 HUD 读 prefs 域的 key 名未确认（TBD），面板上线前必须 dump。
- **HUD 补丁脆弱**：挂在闭源 Swift 视图上，iOS 更新或 HUD 内部变化可能失效——已有开关兜底，失效表现 = 恢复磨砂（非崩溃）。
- **中央注入不均匀**：Eggplant/bili-universal 类中央不可达 App，白名单勾了也无效（副本注入的 App 由 postinst 刷新覆盖）。白名单页可对「已配置但勾选仍无效」情况留反馈入口，不承诺解决。
- **PAC 纪律**：引擎新增代码若引入自有类/块，即触发硬规则 8（必须转 CI）——设计上已规避，实施时守住。
