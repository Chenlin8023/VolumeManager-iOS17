## 一、已定案的事实（全部有实机证据）

### 架构演进史（每版都有 .ips/diag 铁证）
| 版本 | 形态 | 结果 | 真因 |
|---|---|---|---|
| v1/v2 初版 | 无 NSPrincipalClass | 点入口即崩 setExtendedLayoutIncludesOpaqueBars | **Info.plist 缺 NSPrincipalClass**（PSBundleController 从 principalClass 创建根控制器） |
| v2 修复后 | PSListController + getter + 自定义 ivar | 页面开但**空表** | specifiers 只写自定义 ivar，**基类 `_specifiers` 未填充**（PS 自己的 delegate 读它） |
| v4 壳+自绘 | loadView 替换视图 + delegate=self | **卡死**（hang .ips bug509） | **导航栏搜索栏布局死循环**（主线程栈实锤：`_UISearchBarLayout prepareBaseConfigurationForSublayout` → objc_msgSend 烧 CPU 9s）——PSListController 搜索机制与被替换视图状态互斥 |
| v4.1 中介 | delegate=VMPTableMediator | 仍卡死 | 中介没堵住 PS viewDidLoad 内部的 reloadData 路径 |

### v5 的关键认知（新会话必须知道）
1. **PSListController 子类绝不能碰 loadView**——替换视图会让基类搜索机制半初始化 → 导航栏搜索栏布局死循环（iOS 17 新增的 nav-attached search bar）
2. **specifiers 供给 = KVC 写基类 ivar**：`[self setValue:specs forKey:@"_specifiers"]`（CI 头不声明该 ivar，KVC 是唯一通道）；getter 覆写仅在 ivar 空时构建
3. **代码构建开关必须给真 get/set selector**——`set:NULL` = 渲染但推不动（实机踩坑）
4. **cell: 参数 = PSCellType 枚举名**（PSSwitchCell 等，不是字符串）
5. **总开关/混音 = 文件通道（v5.4 定案）**：旧面板/闭源栈全程不用 CFPreferences——
   v5.3 的"cfprefsd 缓存回冲"前提**有误**（闭源面板/HUD/主模块都不 import 任何 CFPreferences* 符号）。
   v5.3 实机（diag(15)）：开关+注销才生效 = cfprefsd 延迟落盘，通知到达时 HUD 读到的文件还是旧值。
   v5.4 改回 `writeToFile:atomically:` 读改写 + 写完 post（见下条 RE 细节）
6. **闭源栈实时刷新机制（2026-11-19 Ghidra 反编译实锤，函数级）**：
   - HUD `VolumeManagerSBHUD.dylib` 观察 **两个** Darwin 通知：`settingOnChanged`（回调 FUN_0000f9a4→FUN_00008c28）
     和 `showVMHUD`（回调 FUN_0000fa9c）；**每次收到通知都重新读 prefs 文件**并刷新
     `isEnabledManagementAppVolume`(Bool) / `HUDDisplayMeetTheConditions`(String，默认"1") 两个全局缓存；
     HUD 窗口显隐在下次音量键事件 / showVMHUD 时按缓存裁决（toggle 本身不主动弹窗——旧面板行为也是如此）
   - HUD 自己在音量调节后写 volumeInfo.plist 并 post `onChangeHUDVolume`
   - **旧面板写开关** = `initWithContentsOfFile:` → `setObject:forKey:` → `writeToFile:atomically:`（整字典读改写）
     → post `settingOnChanged`；panel 二进制里有 `HUDDisplayMeetTheConditions`/`isEnabledMixable` 键（也是文件通道写）
   - 引擎 `VMPrefsEnabled()` / `VMMixLoadConfig` 全部读文件 → 三方（HUD/引擎/旧面板）共享同一 plist 文件，
     唯一 Deviation 是 v5.3 的我们走 CFPreferences——v5.4 已对齐
7. **混音双 key 修正**：`isEnabledMixable` 的读者是**闭源主模块**（HUD 二进制里没有该键，旧面板二进制里有）；
   `vmMixEnabled` 是我们引擎的键（HUD 也不认识）——v5.4 两个键同一次读改写落盘
8. **白名单文件写入无冲突**（appwhitelist.plist 是我们自有文件，非 CFPreferences 域）——引擎三态裁决已实机验证 ✓（vmaq.log：未勾选 → 白名单=2 不装挂钩）
