# 04 · 大版本规划前现状摘要（控制面板 / 音量面板 / 应用白名单）

> 本文是大版本更新的交接底稿：只整理**已定案的事实与约束**，不做设计决策。
> 设计与实施在新会话进行。基线版本 = v1.3.4（2026-11-18 已发布，GitHub + root-site 均已上架）。

## 一、需求（用户 2026-11-18 提出）

1. **控制面板**改造（现为原版闭源面板，只做过文案净化）
2. **音量面板**（HUD）改造

## 二、引擎现状（v1.3.4 事实）

### 注入与生效链路

- **注入入口**：`VolManAudioQueue.plist` 过滤器，`Bundles = (com.apple.UIKit)` → **所有加载 UIKit 的进程都被注入**（rootless 中央注入，ElleKit/substrate 机制）。
- **进程内决策**（ctor）：配置缺失 → 不装音量挂钩（混音层照装）；Widget/Today 扩展进程（PluginKitPlugin 容器）→ 全跳过；配置存在但本 App 未匹配 → 装挂钩、系数 1.0（**当前没有任何白名单语义，名单外 App 也全装**）。
- **两种注入形态**（QQ阅读/起点读书 2026-11-18 实测定案）：
  - 中央动态注入 = 默认形态，升级自动跟随（抖音/两阅读 App 均此形态）；
  - JailFools 拷贝注入（`<App>.app/Frameworks/` + LC_LOAD + `.jailfools`）= 副本文件的存在会**抑制中央注入**（同进程双实例，先于 jbroot ctx 就绪的实例 0 命中不装挂钩）；v1.3.2 起 postinst 自动刷新现存副本。
  - 注意：**不是所有 App 中央注入都可达**（Eggplant/bili-universal 删副本后 0 命中，已放弃）。白名单功能设计时要考虑这个不均匀性。
- **装完 deb 必须 respring 一次**（中央注入注册需要），这是 v1.3.x 实锤的纪律。

### 引擎分层（Tweak.xm ~1750 行，全在 `src/VolManAudioQueue/`）

| 层 | 挂点 | 说明 |
|---|---|---|
| 渲染回调层 | `AudioUnitSetProperty(kAudioUnitProperty_SetRenderCallback)` | 包装原回调逐样本缩放；格式感知（Float32/64/SInt16/32/8），不认识的原样放行；ctx 表 512 槽（静态 BSS，进程生命周期，match 复用） |
| 备用层 | AVPlayer / AVAudioPlayer / AVSampleBufferAudioRenderer 的 `setVolume:` + `play` | 基准登记表（gBase 弱键）+ echo 防护（gLastWritten，v1.3.1）+ 0.5s 回写；AudioQueueSetParameter 只在调用瞬间缩放（无登记无回写 = B站实时缺口，用户已否决单独立项） |
| 混音层 | `setActive` / `setCategory` 四变体 + 私有 `privateSet*` | 每次激活前重申 MixWithOthers；与音量配置解耦、无条件安装；录音类不改类别 |
| 刷新引擎 | 0.5s 轮询（config size+mtime）+ 3 个 Darwin 通知 | `settingOnChanged` / `onChangeHUDVolume` / `showVMHUD` |

### 探针（v1.3.3/1.3.4 新增，排障标配）

- 每条日志带 `pid=N`（区分进程 / 双实例）；
- RC 探针：渲染回调真实执行统计，30s 且计数有变化才输出一行（`缩放+0`=包装单元不在发声路径；`缩放+X` 持续增长=确实在缩放）；
- 包装行带采样率；`vmaq-debug` 空文件 = 详尽探针明细。
- **教训**：日志全绿 ≠ 听感有效（v1.3.1 时代的教训），听感是唯一裁决标准，探针负责把争议变可测。

## 三、面板 / HUD 现状（大版本的主战场）

- **均为原版闭源二进制**：`VolumeManagerPrefs.bundle`（设置面板）+ `VolumeManagerSBHUD.dylib`（音量 HUD），Swift + Orion 编译。
- full 包只做过**文案净化**：打包期对原版面板二进制里的推广/收款/链接文案**等长清空**再重签（长度不变保证 Swift 字面量长度常量成立）+ 运行时 VolManPrefsClean 摘 specifier / 拦链接。
- **构建约束（Jikan 教训，硬规则）**：含自有 ObjC 类 / 捕获块的东西，本地 clang19 缺 Apple PAC 指令生成（栈 block isa），**不能本地编译**；面板/HUD 若要改功能，路径只有：
  - (a) 改原版二进制（数据补丁级别，受限）；
  - (b) 自写替代面板（要过 Apple 工具链：仓库 CI / Theos 官方源预编译），或用纯配置驱动方案（PreferenceLoader plist 面板，无自有 ObjC 类则本地可编）；
  - (c) HUD 替代同理。
- 原 HUD 与引擎的交互面 = Darwin 通知：`onChangeHUDVolume`（HUD 调音量）、`settingOnChanged`（面板）、`showVMHUD`。自写面板/HUD 只要发这三个通知 + 写对配置文件即可与引擎解耦。

## 四、配置与数据（已由用户导出确认）

- **音量配置**：`/var/jb/var/mobile/Library/VolumeManager-sunshinesong/volumeInfo.plist`
  - 格式：`root = { <bundleId> : { volume: <float 0..1>, appName: <中文显示名> } }`
  - 兼容字符串数值存储；沙箱 App 的读取兜底副本：`/var/mobile/Library/Preferences/com.local.volmanaudioqueue.appvolume.plist`

- 引擎多路径探测 8 个候选（jbroot / plain / Preferences 同步副本 / App 容器 Documents / /tmp）。

## 五、白名单的现状差距与待决问题（新会话的工作清单）

现状差距：**当前所有 UIKit 进程都装挂钩**（未匹配也装、混音层无条件装），无任何白名单/黑名单语义。

待决问题（设计前必须回答）：

1. **白名单落在哪一层**：
   - filter 层（改 `VolManAudioQueue.plist` 的 Bundles 枚举 → 静态，新装 App 要重发 filter；改完需 respring）；
   - ctor 层（引擎启动时读白名单决定装/不装挂钩——现骨架已支持"配置缺失不装"，加白名单语义改动最小）；
   - 两者结合（filter 保持宽口径，ctor 精确裁决）。
2. **白名单存储**：volumeInfo.plist 加 key？独立 plist？与现有 `vmaq-path.txt` / `vmaq-debug` 等旁路文件的风格一致性。
3. **名单怎么来**：用户手动勾选（需面板支持）vs 扫描已装 App（LSApplicationWorkspace？）自动列清单 vs 按"音乐/阅读"类别自动判定。
4. **面板/HUD 改造路线**：改闭源原版 vs 自写替代（见 §三构建约束）。自写的话与引擎的契约 = 3 个 Darwin 通知 + 配置文件格式。
5. **混音层是否也随白名单收窄**：混音层目前无条件安装（多 App 同播的关键），收窄到白名单 App 会改变同播行为——需明确产品语义。
6. **兼容迁移**：老用户升级后现有 volumeInfo.plist 里的 App = 事实上的白名单种子？空名单时的行为（全装=现状 or 全不装）。
7. **JailFools 副本兼容**：白名单变化是否要触发 postinst 副本刷新/清理逻辑。

## 六、工程与发布纪律（照抄，别重新踩）

- **构建**（WSL）：`bash /mnt/d/WorkBudy/iOS-Tweaks/VolumeManager/tools/build-rootless.sh [full|patch|all]`；产物 → `iOS-Tweaks/release/`；构建含执行位硬断言与 CRLF 清理。
- **双发行形态**：仓库 = rootless（`ARCHS=arm64`、`/var/jb` 前缀、`@rpath/CydiaSubstrate`）；本地 `vm-fix*` = roothide 线（勿互相覆盖）。
- **验证纪律**：编译全绿 ≠ 能用；实机验收 = 日志头版本行 + 听感；装完必 respring；"失效"先用 RC 探针裁决。
- **发布**：GitHub `git -c http.proxy=http://127.0.0.1:7897 push`（TUN 关时）；root-site 走 repo-meta.json + `make_repo.py --check`，旧版本只增不删，发布后线上回抓 sha256；发包/推 GitHub/改源站前必须先问用户。
- **环境**：jbroot ID = `.jbroot-D275DCAA1B5F9B0E`（重启越狱会变）；iPhone 15 Pro / iOS 17.2.1 / RootHide。
- **日志位置**：沙盒 App → 各自容器 `Documents/vmaq.log`；可写中央的 App → 中央配置目录。
- **挂账**：B（备用层 0.5s 回写节流）、C（ctx 耗尽失败日志，Tweak.xm VMObtainCtx NULL 静默放行处）；AQ 登记表（用户已否决单独立项）。
